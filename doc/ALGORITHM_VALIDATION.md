# 算法与 Android 验证（2026-10-10）

本文件记录当前实现。早期 GPS 调试文档中的 15/20 km/h 限速和测试模式不再代表当前默认值。

## 数据与状态规则

- Core 是纯 net10.0 类库；测试直接引用它，不复制算法，不需要手机或 MAUI workload。
- 步频使用真实单调毫秒时间戳，窗口 8 秒，至少 1 秒有效跨度；连续 3 秒无新步数后归零。
- 逐步事件用首末事件的间隔估计步频。累计传感器只记录真实批量计数差值，不制造逐步时间戳。
- 读取步频不丢弃仍有效的零计数基线；过期后保留时间顺序约束，但允许新零基线开启新的估计窗口。
- 重置清计数和步频；停止/恢复保留本次步数，但重新建立硬件累计基线，排除暂停期间的步数。
- Android 优先选择唤醒型 StepDetector 计数及计算步频；StepCounter 作独立核对。有累计传感器但没有逐步检测器时，使用累计差值。两条通道不相加。
- 加速度兜底使用合力去重力、按实际采样间隔计算的滤波系数及峰值检测；最小峰间隔 200ms，超过 1 秒断流重新预热。
- 运动会话时长只累计 Running 区间；暂停时控制器停掉 GPS 与计步来源，会话同时拒收非 Running 输入，双保险。平均步频 = 本次步数 / 跑动分钟数，不是采样均值；采样只供图表与记录。
- 距离与步数不在会话里重算，会话镜像追踪器与计步器的累计值；GPS 过滤与计步基线规则不变。
- 课程推进：阶段边界按计划值累加（时长阶段按时长、距离阶段按距离），晚到的采样不把误差带进下一阶段；另一维从切换时的实际值起算；一次更新可跨多个阶段；只在 Running 中推进，暂停期间会话时长不走，阶段自然暂停。
- 记录：会话结束且跑动时长 ≥ 5 秒才落盘，字段直接取自会话（时长不含暂停，平均步频 = 步数 / 跑动分钟）；时间以 UTC 存储，界面显示时转本地。
- 配速：只从会话的（跑动时长, 累计距离）序列推算，不用 GPS 瞬时速度——一个跳点就能造出假的"最快配速"。实时配速 = 最近 30 秒窗的 Δt/Δd（跨度 ≥ 5 秒、距离 ≥ 10 米；最近一条采样超过 10 秒未更新则不显示）。最快 / 最慢 = 以每个"前进了"的采样为终点、刚好覆盖 ≥ 100 米的最紧滑窗取极值；上一次前进超过 10 秒再动则断段、窗不跨段（等红灯不算最慢配速，几秒的犹豫算）；慢于 20 分钟 / 公里视为站着不计。平均 = 跑动时长 / 距离。距离序列随记录落盘，旧记录没有，最快 / 最慢显示 —。

## GPS 默认参数

| 参数 | 默认值 |
|---|---|
| 最小距离 | 2m |
| 最大表观速度 | 45km/h |
| 最小有效采样间隔 | 0.3s |
| 最大水平精度半径 | 20m |
| 最长样本年龄 | 10s |
| 自动分段空档 | 超过 15s |
| 当前速度有效期 | 3s |

距离门限取最小距离与前后水平精度半径之和的较大者。误差圈内的往返抖动不累计距离。
精度是统计估计，不是严格误差上界；该策略不保证消除所有缓慢漂移，也会牺牲低质量定位下的短距离灵敏度。

有效原生速度优先用于实时速度；没有原生速度时使用合格位移估算。静止新观测和采样超时均不沿用旧速度。
平均速度包含连续录制段内静止时间，排除显式暂停与长时间断流的段间空白。
BeginSegment 保留累计数据但断开轨迹；Reset 清全部运动数据。

Android 使用 Location.ElapsedRealtimeNanos 与 SystemClock.ElapsedRealtimeNanos 的同一开机时钟，
经 SensorClock 固定 UTC 锚点映射后送入 Core。不要将 GPS 的 Location.Time 直接与手机墙钟比较：
真机已经复现过 GPS UTC 略超前，从而把有效位置错误判为未来点。

## 自动回归

运行命令、用例范围和覆盖率设置见 tests/README.md。
用例覆盖正常数值、无效输入、时间边界、重复/倒序样本、暂停/重置和定时读取与输入回调交错。

加速度合成信号使用 90/120/180/210/240 SPM 与 25/50/100Hz 的组合，允许最多 1 步首尾暂态差。
它验证滤波及峰值统计行为，不证明手持、口袋、摆臂、原地踏步或振动环境中的真实识别精度。

## 真机检查边界

Android 15 手机已用于安装、首次权限、前台服务和传感器回调检查。
首轮非唤醒型逐步检测：用户报告 20 步，应用记录 13 步。
第二轮唤醒型传感器：最后一次基线之后逐步检测回调恰为 20 个，累计传感器独立报告 22 步。
因此保留两者的诊断差异，不通过加权、相加或固定补偿把结果强行凑到人工步数。

GPS 首轮系统定位开关关闭；第二轮收到真实位置，发现并修正采样时间基准问题。
30~55m 精度的点应被拒绝；高精度点在正确时间基准下才用于轨迹。

第三轮真机已确认：20 步区间收到 20 个唤醒型逐步事件，停止后步频归零。
GPS 使用单调时钟后有效点被接受，持续每秒收到约 4m 精度的定位，未再出现未来点误拒。
用户确认是在室内来回走或原地踏步；该场景下位移低于误差门限，累计距离为零并不代表没有定位。
硬件还表现出“开始走动时先确认约 10 步，再集中上报”的行为，极短的 5 步测试不足以评估其最终计数。
界面因此增加了硬件延迟提示、GPS 精度及过滤状态，并将公里显示改为三位小数，便于调试小距离。

自动测试包含 219 个用例全部通过（2026-10-09 新增运动会话 21 例、课程推进 11 例、记录生成 3 例；2026-10-10 新增配速 15 例、距离采样 1 例），Core 行覆盖率 100%、分支覆盖率 98.7%。
GPS 室外已知路线误差、加速度真机精度和长时间锁屏尚需另行实测，未据合成测试宣称通过。

后续精度验收应采用已知长度的连续路线、人工计数和多次重复，分别测前台、锁屏及加速度兜底。
不要把短距离 GPS 的两位小数显示或单次 20 步测量当作全面精度结论。
